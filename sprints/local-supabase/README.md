# تشغيل YmPharma محليًا باستخدام Docker

هذه الحزمة تكمل فرع التقارير المالية، وتشغّل **منشأة تدريب واحدة** على جهازك. التطبيق الموجود هو Next.js/React، وليس Vite. لا تستبدل موقع Oracle المنشور ولا تتصل بقاعدة إنتاج أو ترحّل معاملات خارجية.

## التشغيل على Windows

المطلوب: Git، وNode.js 22 أو أحدث، وDocker Desktop يعمل بوضع **Linux containers**. نزّل الاعتماديات وصور Docker أول مرة أثناء وجود الإنترنت. لا تحتاج حساب Supabase سحابيًا أو مفتاحًا يُرسل في المحادثة.

افتح PowerShell. للحصول على نسخة مستقلة من هذا الفرع:

```powershell
git clone --branch tooling/local-supabase https://github.com/dahsamtransport-source/pharmacy-erp.git ympharma-local
cd ympharma-local
npm ci
npm ci --prefix sprints/01-database --ignore-scripts
npm run local:doctor
npm run local:start
npm run local:seed
npm run local:smoke
npm run local:dev
```

إذا لديك checkout لهذا الفرع بالفعل، نفّذ الأوامر بدءًا من `npm ci` داخل مجلده. لا تنسخ الملفات فوق مشروع آخر. تعمل أوامر npm نفسها في Linux/macOS مع Docker محلي.

افتح التطبيق على **http://127.0.0.1:3000**. افتح لوحة Supabase Studio على **http://127.0.0.1:54323**. تظهر لوحة التدريب فارغة ماليًا حتى تُدخل مشتريات ومبيعات فعلية ضمن التدريب.

## تسجيل الدخول والتجربة

بعد نجاح `local:seed`، افتح الملف محليًا:

```powershell
notepad .local\training-accounts.json
```

ستجد ستة حسابات تدريب: `owner` و`manager` و`accountant` و`cashier` و`pharmacist` و`inventory`، مع بريد وكلمة مرور عشوائية مختلفة لكل حساب. هذا الملف مستثنى من Git؛ لا ترفعه أو ترسله أو تستخدم كلمات مروره في الإنتاج. احتفظ بمجلد العمل في حساب Windows خاص بك، لأن صلاحيات الملفات Unix لا تعادل قوائم وصول Windows.

1. سجّل الدخول بحساب المالك، واختر منشأة التدريب ومخزن التدريب.
2. افتح المشتريات، واختر «مورد تدريب» و«صنف تدريب غير طبي»، وأدخل رقم فاتورة فريدًا وتشغيلة وصلاحية مستقبلية وكمية وتكلفة.
3. اعتمد عملية التدريب، ثم سجّل الخروج وادخل بحساب الكاشير. ابحث عن الباركود `TRAINING-001` وأنشئ عملية بيع.
4. الكاشير لا يملك التقارير المالية. ادخل بحساب المحاسب للتحقق من ميزان المراجعة وقائمة الدخل والطباعة.

العملة YER والمنطقة الزمنية Asia/Aden هنا **إعداد تدريب معلن** وليستا إقرارًا بسياسة المنشأة الإنتاجية. لا توجد أدوية سريرية حقيقية أو مرضى أو فواتير مزروعة في البيانات. القوائم الأولية فقط تُنشأ، ثم تعالج العمليات عبر RPC المعتاد.

## الأوامر المتاحة

| الأمر | الوظيفة |
|---|---|
| `npm run local:doctor` | فحص Node وCLI وDocker المحلي بنمط Linux |
| `npm run local:start` | إنشاء شبكة loopback وتشغيل خدمات التدريب بملفات الترحيل الأصلية |
| `npm run local:status` | عرض الجاهزية والعناوين دون المفاتيح |
| `npm run local:dev` | تشغيل الواجهة بإعداد Supabase المحلي دون تعديل ملف اتصال قائم |
| `npm run local:env` | إنشاء `.env.local` بمفتاح publishable العام فقط؛ يرفض استبدال إعداد مختلف قائم |
| `npm run local:seed` | إنشاء حسابات وبيانات تدريب أولية، واستكمال تشغيل سابق دون تغيير كلمات مرور قائمة |
| `npm run local:smoke` | 25 تحققًا عبر Auth وPostgREST الفعليين: الدخول، العضوية، أدوار التقارير، وحجب مخطط التكلفة |
| `npm run local:migrate` | تطبيق ملفات الترحيل الجديدة محليًا دون حذف البيانات |
| `npm run local:stop` | إيقاف هذا المشروع فقط مع الاحتفاظ بالبيانات |
| `npm run local:test-db` | إنشاء PostgreSQL 16 مؤقت مستقل، وتشغيل 54 اختبار SQL/RLS و8 اختبارات تزامن، ثم إزالته |
| `npm run test:local-tools` | اختبارات حواجز الأمان والتدريب المحلية التي لا تتطلب Docker |

أمر `local:test-db` يستخدم منفذًا عشوائيًا مربوطًا بـ127.0.0.1 وقاعدة `ympharma_test` وكلمة مرور مؤقتة. لا يستخدم قاعدة Supabase التي تعمل عليها. يحتاج تنزيل صورة `postgres:16` أول مرة. عند انقطاع قسري للجهاز تحقق من الحاويات التي تحمل الوسم `com.ympharma.disposable-test=true`؛ لا تحذف حاويات أخرى.

## حفظ البيانات وإعادة التهيئة

`local:start` و`local:stop` لا يحذفان بياناتك. لا تستخدم `supabase stop --no-backup`. لا تدمج ملفات SQL في ملف واحد جديد، ولا تشغّل `supabase init` في جذر هذا المستودع: يوجد هناك مخطط تاريخي مختلف.

المسار المعزول هو `sprints/01-database/supabase`، ويستخدم ملفات الترحيل الخمسة الموجودة بترتيب أسمائها. لم ننسخها أو نعدّلها. **لا تشغّل محاكي `tests/harness.mjs` على قاعدة Supabase**: هو يستبدل `auth.uid()` داخل قواعد الاختبار المؤقتة فقط.

لإتلاف بيانات التدريب وإعادة البداية عمدًا، أوقف الواجهة أولًا ثم نفّذ:

```powershell
npm run local:reset -- --confirm-local-data-loss
npm run local:seed
npm run local:smoke
npm run local:dev
```

هذا يمسح أيضًا مستخدمي Auth المحليين، ويؤرشف ملف كلمات المرور القديم محليًا. لا يوجد reset تلقائي عند البدء. لن تقبل الأدوات `--linked` أو عنوان قاعدة بعيد أو إعداد Docker بعيدًا. لا تستعمل هذا المسار لتخزين بيانات إنتاج تحتاج حفظًا مضمونًا؛ إيقاف الحاوية ليس نسخة احتياطية خارج الجهاز.

## ما يعمل دون إنترنت وما لا يعمل

- بعد تجهيز الاعتماديات وصور الخدمات، يمكن تشغيل التطبيق وPostgreSQL وAuth وPostgREST وStorage محليًا. تحقق عمليًا على جهازك بفصل الإنترنت وإعادة فتح التطبيق وإدخال عملية تدريب ومراجعة التقرير.
- أُصلح منع الواجهة لطلبات localhost عندما تصبح `navigator.onLine=false`. هذا يسمح بطلب حقيقي إلى الخادم المحلي؛ لا يصطنع نجاحًا عند إطفاء Docker، ولا يلغي منع التكرار أو التحقق في الخادم.
- إن توقف Docker أو PostgreSQL فلن يتم الحفظ. لا توجد في هذه الحزمة طوابير مبيعات مستقلة عن قاعدة البيانات أو مزامنة إلى الإنتاج.
- OpenAI وWhatsApp وGoogle Drive وERP الخارجي تحتاج اتصالًا وإعدادًا مستقلًا. البريد المحلي يُعرض في صندوق البريد التجريبي ولا يرسل إلى العملاء. Edge Functions الخارجية وAnalytics معطّلتان هنا.
- المنافذ محصورة على الجهاز نفسه. `localhost` على الجوال يعني الجوال، لا الكمبيوتر. اختبار Android عبر شبكة محلية أو نشر إنتاجي يحتاج إعدادًا منفصلًا؛ لا تفتح منافذ Studio أو قاعدة البيانات للإنترنت.
- Supabase Studio/SQL Editor يعمل بصلاحيات إدارية؛ عرض البيانات فيه وحده لا يثبت صحة RLS. استخدم `local:smoke` وحسابات الفريق واختبارات SQL لهذا الغرض.

## معالجة الأعطال

- **Docker غير موجود/متوقف:** شغّل Docker Desktop بوضع Linux containers ثم أعد `local:doctor`. لا حاجة لإدخال مفاتيح سحابية.
- **منفذ 54321–54324 مشغول:** راجع التطبيق الآخر الذي يستخدم المنفذ؛ الأداة لا توقف مشروعاتك الأخرى تلقائيًا.
- **`.env.local` قائم:** اتركه كما هو واستخدم `local:dev`؛ إعداد العملية يتقدم على ملف البيئة، ولن يتصل بالعنوان السحابي المخزن فيه.
- **ملف التدريب غير مطابق لـAuth:** لم تُغيّر كلمات المرور. راجع هل أُعيد ضبط القاعدة يدويًا أو حُذف ملف التدريب. استخدم reset المعلن فقط إذا وافقت على حذف بيانات التدريب الحالية.
- **`seed.lock` بقي بعد إغلاق قسري:** تحقق من توقف كل عمليات `local:seed`، ثم احذف ذلك الملف فقط وأعد المحاولة.
- **ترحيل جديد:** استخدم `local:migrate`، وليس `local:reset`.

التهيئة المحلية ليست شهادة امتثال أو إثباتًا لاجتياز اختبارات الأجهزة. انظر [تقرير التحقق](TEST_REPORT.md) لما نُفّذ بالفعل وما لم يُختبر.
