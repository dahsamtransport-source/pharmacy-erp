# تقرير التحقق — Sprint 2

التاريخ: 2026-09-20. الفرع: `sprint2/ympharma-frontend`. قاعدة العمل: `1447c6e7ee959f1513625da1e181539ef813a951` من Sprint 1.

## النتائج المنفذة

| الفحص | النتيجة |
|---|---|
| `npm test` | 24 اختبارًا ناجحًا في Vitest/jsdom |
| `npm run test:db` | 41 اختبار SQL/RLS ناجحًا على PostgreSQL داخل PGlite؛ تشمل اختبارات Sprint 1 السابقة |
| `npm run lint` | ناجح دون أخطاء أو تحذيرات ESLint |
| `npm run build` | بناء إنتاج Next.js ناجح؛ الصفحة الرئيسية مولّدة وواجهة API القديمة محفوظة |
| `npm run typecheck` | ناجح مع TypeScript strict |
| فحص HTTP للإصدار المبني | الصفحة تعيد 200 مع RTL وحالة عدم الاتصال، ومسار AI القديم يرفض الطلب بلا اعتماد بـ401 |
| `npm audit --omit=dev` | صفر ثغرات معروفة مُبلّغ عنها في اعتماديات التشغيل وقت الفحص؛ ليس تدقيقًا أمنيًا شاملًا |

التحذير البيئي `npm Unknown env config http-proxy` لا يتعلق بكود التطبيق. الاختبارات ذات البيانات المصطنعة ليست اتصالًا بقاعدة حسابات المستخدم.

## سلوكيات الواجهة التي اختُبرت

1. لا تُعرض مبالغ المقطع التجريبية عند غياب البيانات.
2. نطاق مبيعات الكاشير وفتح POS يعكسان البيانات والاختيار الفعليين.
3. طلب البيع يرسل العبوات والكميات فقط؛ لا يرسل السعر أو الإجمالي أو approved.
4. رفض الخادم يحافظ على السلة ويظهر الخطأ.
5. عبوتان للصنف نفسه تبقيان سطرين منفصلين.
6. الأصناف المحتاجة وصفة لا تدخل مسار بيع بلا مراجعة.
7. الكاشير لا يستدعي التقارير المالية.
8. الموردون من عقد القراءة، بلا معرفات ثابتة في الشاشة.
9. إدخال تشغيلة شراء كاملة يرسل رقمها وصلاحيتها وتكلفتها الدقيقة ثم يمسح البنود بعد التأكيد.
10. الطباعة تُستدعى بعد ضغط المستخدم، مع توضيح حالة ERP.
11. حساب المال والتقريب بأعداد صحيحة، بما في ذلك رصيد -0.01.
12. لا تُختلق نسبة نمو عندما تكون قيمة أمس صفرًا.
13. المهلة الشبكية تحتفظ بالمعرف عند إعادة إنشاء خدمة الطلبات.
14. تغيير السلة أثناء وجود نتيجة مجهولة يُرفض.
15. رفض قاعدة البيانات المؤكد للمحاولة الأولى يحرر مرجعها.
16. فشل قراءة الإيصال بعد نجاح التسجيل لا يمحو المرجع.
17. المطابقة بالمرجع تعيد المستند دون إنشاء بيع جديد.
18. إعادة المحاولة تبحث عن النتيجة أولًا.
19. رفض محاولة لاحقة لا يمحو مرجع محاولة سابقة مجهولة.
20. المراجع معزولة بين المستخدمين والمنشآت.
21. النقر المزدوج لا يبدأ إرسالين.
22. لا إرسال مالي عند انقطاع الإنترنت.
23. تغيير الهوية يُسقط البيانات السابقة والاستجابة المتأخرة.
24. غياب الخدمة ينهي حالة التحميل دون مؤشر أبدي.

اختبارات SQL السبعة المضافة تشمل سياق العضويات، مجموع مبيعات الكاشير الخاص، عدم تسريب التكلفة في دليل الأصناف، ملكية المستند، صلاحيات التقارير، الموردين ومنح تنفيذ الدوال، وعدم عرض صفر كاذب للمبيعات المحجوبة عن أمين المخزن.

## حدود التحقق والعوائق

- محاولة فتح خادم التطوير في المتصفح المتاح رُفضت بـ`net::ERR_BLOCKED_BY_CLIENT` على `http://localhost:3022`. لذلك لم يكتمل اختبار المتصفح المرئي أو الطباعة الفعلية؛ نجاح اختبار استدعاء `window.print` لا يثبت تنسيق ورقة مطبوعة.
- لم تُختبر أجهزة Android أو Windows أو قارئ باركود أو طابعة فعلية. توجد قواعد responsive وreduced-motion في الكود، وتحتاج قبولًا بصريًا على الأجهزة.
- لم تُضبط بيئة Supabase لهذا الفرع؛ لم يُختبر اتصال Auth/PostgREST مستضاف ولا حسابات فريق حقيقية. اختبارات الواجهة تستخدم عقودًا محاكية، واختبارات SQL تنفذ الهجرات والأدوار فعليًا في قاعدة اختبار معزولة.
- اختبارات PostgreSQL الثمانية ذات الاتصالين من Sprint 1 ما زالت غير منفذة. GitHub Actions سبق أن رفض بدء المهمة لأن حساب GitHub مقفل بسبب الفوترة (run `35481232561`، job `105999306057`). ملف CI الجديد موجود؛ لا نعتمد عليه كدليل نجاح حتى يُشغّل.
- لا تغييرات على قاعدة الإنتاج أو موقع Oracle المنشور، ولا معاملات مالية حقيقية، ولا اختبار لموصلات OCR/WhatsApp/ERP.

حالة التسليم: كود واجهة قابل للبناء والمراجعة مع حماية عقود البيانات واختبارات محلية ناجحة؛ جاهزية الإنتاج غير مثبتة.
