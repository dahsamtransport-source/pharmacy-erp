# YmPharma — Sprint 2: الواجهة والتكامل مع عقود البيانات

حزمة مراجعة مبنية فوق فرع Sprint 1 وطلب المراجعة #5. تُبقي Next.js الموجود في المستودع، وتضيف React/TypeScript وTailwind وFramer Motion وLucide وخط Tajawal محليًا. لم يُنشر هذا التغيير على موقع Oracle الحالي ولم تُعدّل قاعدة إنتاج.

## ما يعمل في الكود

- لوحة عربية RTL: بطاقات فعلية للمبيعات والنواقص والصلاحية، حركة سبعة أيام، آخر المستندات، تنبيهات مخزون محلية، قوائم قابلة للطي، قوائم جوال وحالات تحميل وفشل وعدم اتصال.
- لا توجد أرقام تجريبية ضمن التطبيق. بيانات الاختبار موجودة في `tests/frontend` فقط. شارة الاتصال تعني جلسة ومساحة عمل مهيأة، ولا تعني نجاح كل طلب؛ أخطاء الطلبات تظهر بصورة مستقلة.
- تسجيل الدخول ببريد وكلمة مرور حساب Supabase موجود. لا حساب admin افتراضي، ولا كلمة مرور في المصدر. الدور من جدول العضويات المحمي؛ الاسم التعريفي فقط من بيانات المستخدم.
- نقطة بيع نقدية أو بنكية: بحث الاسم/الاسم العلمي/الباركود، اختيار العبوة، سلة تحفظ الوحدات المختلفة مستقلة، تعديل الكمية وحذف السطر. مسح الباركود ثم Enter ينفذ البحث؛ اختيار النتيجة يضيفها للسلة. الخادم يحسب السعر والإجمالي ويطبق FEFO والصلاحيات.
- استلام مشتريات: مورد فعلي، رقم فاتورة المورد، عبوات، أرقام التشغيلات، الصلاحية والتكلفة بأربع منازل. يرجع المستند بعد نجاح المخزون والقيد في الخادم.
- المخزون والصلاحية مع صفحات بحث محدودة؛ لا تُرسل تكلفة المخزون للكاشير في عقود القراءة العامة.
- ميزان مراجعة لفترة محددة مع افتتاحي/حركة/ختامي، وقائمة دخل مشتقة من الحسابات؛ للمالك والمدير والمحاسب فقط.
- مستند مسجل قابل للطباعة وتنسيق A4 للتقارير. لا تظهر رسالة «تمت الطباعة» بمجرد فتح مربع الطباعة، ولا يُدّعى الترحيل الخارجي إلى Modern Soft.
- استعادة نتيجة عملية غير محسومة: UUID وبصمة الطلب فقط في `sessionStorage`، مع عزل بحسب المستخدم والمنشأة ونوع العملية. لا تخزين للفاتورة أو بيانات المريض أو JWT أو كلمة المرور. تُبحث النتيجة بالمرجع قبل إعادة الطلب بالمعرف نفسه. رفض محاولة لاحقة لا يمحو مرجع محاولة سابقة انقطع اتصالها.
- عند تبديل الحساب أو الدور أو المستودع، تُعزل حالة الشاشات وتُهمل نتائج الطلبات القديمة. لا تعود إيصالات الحساب السابق إلى الشاشة.

## تشغيل الواجهة

استخدم Node.js 22 حديثًا أو أحدث:

```sh
npm ci
cp .env.example .env.local
npm run dev
```

افتح `http://localhost:3000`. يمكن مراجعة التنقل والتصميم بلا إعداد اتصال؛ تظهر القيم غير المتاحة كشرطة، وتبقى عمليات التسجيل معطّلة.

للإصدار المبني:

```sh
npm run build
npm run start
```

في `.env.local` أو إعدادات بيئة الاستضافة، اضبط **عنوان مشروع الاختبار ومفتاح publishable العام فقط**:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`

الكود يرفض مفاتيح `secret` وJWT القديمة؛ يستخدم مفتاحًا يبدأ بـ`sb_publishable_`. هذه القيم العامة تدخل حزمة المتصفح، ولذلك لا تضع فيها مفتاح `service_role` أو أي سر. متغيرات Next العامة تُقرأ وقت البناء؛ أعد البناء بعد تغييرها. لا ترسل القيم السرية في المحادثة. مسار AI القديم يحتفظ بأسراره على الخادم ولم يُربط بهذه الواجهة.

## إعداد قاعدة اختبار متوافقة

1. أنشئ مشروع Supabase **تجريبيًا فارغًا**. لا تستخدم هجرات التطبيق التاريخية بالتوازي مع هذا المخطط البديل؛ راجع `sprints/01-database/CUTOVER.md`.
2. طبّق ملفات SQL الأربعة داخل `sprints/01-database/supabase/migrations` بترتيب أسمائها باستخدام إجراء الترحيل المعتمد للمشروع. لا تشغّل محاكي `tests/harness.mjs` على Supabase ولا تستبدل `auth.uid()` الحقيقي.
3. أنشئ مستخدم الاختبار في Supabase Auth بالإجراء الآمن المعتاد. نفّذ `sprints/01-database/bootstrap.sql` بواسطة المشغّل مع معرف مستخدم المالك، اسم المنشأة، العملة والمنطقة الزمنية المؤكدة. الملف خاص بـpsql ويُستخدم مرة واحدة؛ ليس نموذجًا للصق كلمات مرور.
4. أضف حسابات الفريق إلى `ym.members` بواسطة مسؤول قاعدة الاختبار. لا تمنح المستخدم كتابة مباشرة إلى هذا الجدول. جهّز الموردين والأصناف والعبوات والفترات ومطابقة الحسابات وحدود إعادة الطلب. إعداد هذه القوائم إداريًا ليس شاشة منفذة في هذا السبرينت.
5. أضف `ym_api` إلى المخططات المعروضة في إعدادات Data API. لا تعرض `ym_private` ولا تمنح وصولًا عامًا إلى جداول `ym`. الهجرات تتضمن منح التنفيذ المطلوبة للدوال.
6. اضبط العنوان والمفتاح العام، ثم تحقق بحسابات المالك والكاشير وأمين المخزن والمحاسب. اختبر الشراء أولًا لإضافة مخزون اختبار، ثم البيع والطباعة والتقارير.

تستخدم دوال القراءة `SECURITY INVOKER` مع تحقق الدور وRLS. لا تمنح `service_role` للمتصفح. إعادة استخدام العضويات والواجهات هنا لا تُثبت وجود إعداد Supabase مستضاف أو نجاح Auth/PostgREST حتى تنفيذ اختبار الطرفين فعليًا.

## ما تبقى خارج Sprint 2

- لا توجد قراءة OCR حقيقية أو إرسال WhatsApp أو تكامل Modern Soft. التنبيهات الموجودة هي تنبيهات المخزون داخل الواجهة.
- واجهة مراجعة الوصفات والتداخلات والتأمين لم تُبنَ في هذه المرحلة. يمنع POS إضافة الأصناف المحتاجة وصفة والخاضعة للرقابة، والخادم يحافظ على ضوابطه السريرية.
- لا يُرحّل بيع أو شراء دون اتصال. السلة في ذاكرة الصفحة وتُفقد عند إعادة التحميل؛ المرجع وحده يبقى داخل التبويب. بعد إعادة التحميل لعملية مجهولة، استخدم «التحقق من عملية سابقة» أو أعد البيانات نفسها. لا تمسح المرجع ولا تنشئ عملية بديلة قبل المطابقة.
- لم تُختبر استعادة مرجع بعد إغلاق التبويب أو حذف مخزن المتصفح؛ يلزم قبل الإنتاج سجل استئناف عمليات على الخادم وسياسة أجهزة مشتركة. ثبات UUID يحمي إعادة **الطلب نفسه** ولا يمنع إنشاء بيع جديد مستقل بمعرف جديد عمدًا.
- إدارة المستخدمين/MFA والقوائم الأساسية والمرتجعات والضرائب والتسويات والنسخ الاحتياطية والتطبيق الأصلي وموصلات الطرف الثالث ليست جزءًا من هذه الواجهة.
- لا ادعاء توافق HIPAA أو اعتماد مالي/طبي أو جاهزية إنتاج. يلزم قبول السياسات المحاسبية والتشغيلية واختبار أجهزة وطابعات فعلية.
