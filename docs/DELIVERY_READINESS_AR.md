## ما تحقق الآن

أضيفت دالة قراءة `ym_api.account_ledger` تعمل بصلاحية المستدعي وتحترم RLS. لا تقبل هوية موظف أو اعتمادًا من المتصفح، ولا تُعدل فواتير أو مخزونًا. تتبع نفس فترة ومركز تكلفة التقرير، وتعرض القيود المرحّلة فقط. تحتفظ الحسابات المعطلة بتاريخها، ويُرفض خلط العملات. الحسابات العشرية دقيقة في SQL وتُراجع في الواجهة باستخدام وحدات نقدية صحيحة كبيرة؛ لا تحويل إلى أرقام عائمة لجمع الأموال.

الإجمالي: **124 اختبارًا ناجحًا**. تشمل الإضافة اختبار تطابق كشف الحساب مع ميزان المراجعة، الفترات والافتتاحي والرصيد المتراكم، الحسابات المعطلة والأرقام الكبيرة، منع الأدوار غير المالية وعزل المنشأة، استبعاد القيود غير المرحلة، رفض نطاق مبالغ فيه، ورفض استجابة تخص حسابًا أو فترة أخرى. اختبارات الواجهة تعمل على jsdom، ولا تعادل اختبار شاشة فعلية.

اختبار 1000/1001 قيد يستخدم بيانات مصطنعة مع قيود التوازن والصلاحيات مفعلة. بعد التحميل الجماعي حدّثنا إحصاءات مخطط الاستعلام صراحةً في قاعدة الاختبار؛ أصبح الاختبار ينتهي دون البطء الذي ظهر مع الإحصاءات القديمة. هذا لا يغني عن قياس خطة الاستعلام والأداء على حجم إنتاجي في PostgreSQL الخادمي.

**لم يُختبر هنا:** Docker Desktop، خادم Supabase الكامل، 25 تحقق Auth/PostgREST المجهز، 8 اختبارات تزامن باتصالات مستقلة، ترحيل البيانات القديمة، الضغط الإنتاجي، الاستعادة الكاملة، أجهزة المستخدم والطابعة، الخدمات المدفوعة أو الربط الخارجي. Docker وأداة تحكم Windows غير متاحين في هذه الجلسة. لم تُطبع أسرار أو تُنشأ معاملات إنتاجية. تقارير الاختبار القديمة محفوظة بتاريخها؛ أعدادها لا تُجمع مع النتائج الحالية باعتبارها اختبارات إضافية.

## ترتيب العمل المتبقي

1. **تثبيت قاعدة التشغيل التجريبية:** تشغيل Docker أو توفير مشروع Supabase اختبار متاح، تطبيق الهجرات بالترتيب، تشغيل اختبارات Auth والتزامن، ومراجعة انتقال المخطط القديم. يُنجز المحرك كاختبار مستقل أولًا.
2. **إكمال دورة المال والمخزون:** واجهات القوائم الأساسية، الأرصدة الافتتاحية والقيود والمرتجعات والمدفوعات وتخصيصها والجرد والورديات والتسويات، ثم قوائم المركز المالي والتدفقات والإغلاق. لكل عملية اعتماد وصلاحيات وتدقيق واختبارات نجاح وفشل.
3. **توحيد المستندات والواجهات:** هوية وصلاحيات ومراجع موحدة بين واجهة الصيدلية والمركز المالي، ثم ترحيل تجريبي ومطابقة أرصدة؛ لا مخزونان يتنافسان على العملية نفسها.
4. **تفعيل الخدمات بالتتابع:** OCR أولًا، ثم الإشعارات، ثم النسخ المشفر والاستعادة، وأخيرًا جسر Modern Soft بعد وثائقه. إعداد الحسابات والأسرار يتم في بيئة الخدمة، لا في المحادثة.
5. **قبول الإنتاج:** سيناريوهات المحاسب والصيدلي والكاشير وأمين المخزن، شبكة منقطعة وTimeout واستعادة ونسخة احتياطية، Windows وAndroid وطباعة، مراقبة ودليل دعم وخطة رجوع، ثم نشر النسخة المقبولة.
