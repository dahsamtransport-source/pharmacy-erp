## Supabase: ما طُبّق فعليًا
مشروع MUSALLY PHARMA نشط. قاعدة MUSALLY ModernSoft Oracle Gateway في حالة INACTIVE؛ لم تُستأنف تلقائيًا ولم يُفحص داخلها أثناء توقفها.

جميع الجداول العامة الـ299 مفعّل عليها RLS، لكن هذا لا يثبت صحة كل سياسة أو كل دالة.

طُبّقت migration `20261008044122_restore_privileged_function_boundaries` على المشروع النشط:
- منع authenticated وanon وPUBLIC من تشغيل apply_retention_policies، والإبقاء على service_role. لم تُشغّل دالة الحذف.
- تحويل billing_activate_plan إلى SECURITY INVOKER لتطبيق سياسات جداول الفوترة الفعلية. كانت الدالة تتجاوز فحص الهوية عند _organization_id = NULL، وتثق بربط الجهة والمؤسسة المقدم من العميل.
- تفعيل الاشتراكات الآن يتبع صلاحيات جدول billing_subscriptions: حساب admin. مدير المؤسسة غير الحامل لصلاحية admin لا يستطيع التفعيل. حساب الخدمة يبقى خاضعًا أيضًا لشروط جسم الدالة القائمة.
- التحقق المحلي أثبت رفض المستخدم العادي ورفض مدير المؤسسة عند كتابة غير مصرح بها، ونجاح المدير مع سجل التدقيق، وصحة صلاحيات الحذف الدوري وإعادة تطبيق migration.
- التحقق المباشر بعد النشر أثبت إزالة SECURITY DEFINER عن التفعيل، ومنع المستخدمين من دالة الحذف مع بقاء الخدمة. لم تُنشأ معاملات مالية أو تُعدّل أرصدة.
- أُعيد تشغيل Security Advisor: عدد دوال SECURITY DEFINER المتاحة للمستخدم المسجل انخفض من 181 إلى 179.

## ما بقي ولا يُعتبر محلولًا
1. بقية تنبيهات Supabase تحتاج مراجعة دالة/سياسة بحسب دورها؛ لا يصح سحب جميع الصلاحيات أو إسقاط جميع الفهارس دفعة واحدة: 179 دالة للمستخدم المسجل، 6 للزائر، حماية كلمات المرور المسربة غير مفعلة، pg_trgm في public، و15 جدولًا بلا سياسات (قد تكون مغلقة عمدًا).
2. تنبيهات الأداء: 462 موضع auth/RLS initplan، 168 سياسة permissive متداخلة، 192 مفتاحًا أجنبيًا بلا فهرس، مجموعتا فهارس مكررة، 454 فهرسًا غير مستخدم، وجدولان بلا مفتاح أساسي. هذه إشارات فحص وليست 1278 أعطالًا مؤكدة؛ يلزم قياس واستعراض سياسات قبل التعديل.
3. QuoteLLM web: 7 تنبيهات (5 عالية، 2 متوسطة) في سلسلة أدوات Tailwind 3، منها braces بلا إصلاح متوافق منشور وفق npm audit وقت الفحص. الترقية الرئيسية تحتاج تحققًا بصريًا؛ لم يُفرض audit fix --force.
4. مكتبات Python قديمة في retrieval-plugin؛ الإصلاح الحالي يعالج عزل الملفات فقط، ولا يدعي تحديث جميع المزودين أو تبعياتهم.
5. فروع موصل متراكبة؛ دمج التصميم السابق كان إلى delivery/readiness-and-ledger، وليس main. يجب دمج سلسلة التغييرات ومراجعة الترحيلات قبل اعتماد main للإنتاج؛ لم تُدمج تلقائيًا.
6. GitHub Actions الحديثة على رأس فرع موصل تُظهر failure دون خطوات منفذة، وسجل المهمة غير متاح. تقارير PR السابقة تذكر قيد الفوترة. النتائج الواردة هنا محلية، وليست نجاحًا في GitHub Actions.
7. لم تُختبر أجهزة أو طابعات أو Oracle الحي أو بوابة متوقفة أو استعادة كاملة أو كل سيناريوهات الإنتاج. اختبارات SQL تستخدم PGlite وليست اختبار اتصالات PostgreSQL متزامنة أو Auth/PostgREST كاملًا.

## منع التكرار
ملفات lock محفوظة، والتثبيت في CI يستخدم npm ci؛ أصبح البناء وفحص الأنواع والاختبارات بوابات واضحة في المشاريع المعدلة. أضيف اختبار SQL للسلسلة التي كانت لا تدخل الاختبارات، واختبارات لحدود الصلاحيات وعزل الملفات. لا يُعتمد نجاح Vite build وحده كدليل على صحة الأنواع.
